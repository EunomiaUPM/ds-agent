pub struct ReachAuthority {
    pub id: String,		(El did de la autoridad "did:web:heimdall.es") (ver mas adelante de donde se saca)
    pub slug: String,		(El nick de como queramos guardarla "Heimdall")
    pub url: String,		(Su url base "https://heimdall.es)
    pub vc_type: String,	(El tipo de vc que se pide) (ver mas adelante de donde se saca)
    pub method: String,		(Como quieres verificar tu identidad para que la autoridad de te una Vc, puede ser "oidc4vp" (significa quiero autenticarme con Vc) o "cert" (quiero autenticarme con certificado)
    pub auto: bool,	(Que el backend haga automatico o no el reclamar la Vc)
				
De donde se saca cada cosa?
url: ES SABIDA PREVIAMENTE POR EL USUARIO y lo introduce el usuario
slug: introduce el usuario el que quiera
id: este se obtiene de que el front fetchee a url/.well-known/did.json esto devuelve un json, y si de ese json cogemos la propiedad "id" que enseña el did, (lo mostraria como info que no se puede modificar en pantalla)
vc_type: este se obtiene de que el front fetchee a url/.well-known/openid-credential-Issuer, que devuelve un json que se ve asi

Lo que el usuario ha de hacer será elegir de un deplegable todos los objetos que incluya el campo "credential_configurations_supported", pues según cual elija el usuario, lo envia al back en el campo vc_type
